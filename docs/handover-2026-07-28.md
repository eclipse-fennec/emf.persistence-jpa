## 1. TL;DR — where we stand

* The **unified query stack is feature-complete**: one canonical EMF expression IR (the Fennec
  Expression Model) → three `QueryProcessor` backends (JPA/JPQL, MongoDB find + aggregation
  pipeline, in-memory), plus CUD commands and a patch-apply engine.
  Two milestones fully closed: *Unified Query* (epic #32, issues #33–#46) and
  *Query IR v2 — Expression Model* (epic #47, issues #48–#58), followed by #60 (patch apply),
  #61 (OSGi wiring of the processors) and #62 (memory backend).
* Active branch is **`snapshot`** (HEAD `0d9bd84`). `main` holds the last release; every push to
  `snapshot` publishes `-SNAPSHOT` artifacts to Sonatype Central snapshots and the docs site.
* **Build state: green as of today**, after fixing an upstream dependency split (§4.1) — that fix
  is *uncommitted* in the working tree. Verified locally: `./gradlew build` successful,
  1002 module/unit tests + 32 OSGi integration tests, TCK 119 tests across all four bindings
  (JPA/Mongo × int/String ids) with a real MongoDB container, 0 failures, 0 skips.
* Everything else that is open is listed in §4 — nothing is half-finished or in a broken
  intermediate state.

### 4.4 Roadmap — what comes next by design

`docs/unified-persistence/concept.md` §18.1 fixes the v1 scope. Item 1 (query SPI + JPA/Mongo
bindings) is **done**. The remaining v1 items, roughly in dependency order:

2. Patch/stream metamodel + **apply/invert engine + conflict check** — partially there:
   `stream.ecore` exists and `UpdateCommand` apply landed with #60; invert and conflict checking
   are not built.
3. **Capture hybrid** — `SnapshotCapture` (keyed diff) + `RecordingCapture` (commit boundary),
   CHANGELOG storage profile, tracking aspect with rules lifted from `emf.util`'s
   sensinact-mapping. Not started.
4. **TIMESERIES profile** (`ATOMIC` arrays only) + retention/housekeeping. Not started.
5. **Fingerprint + snapshot/composite chain** (canonical form, Merkle, content-addressed store,
   upcasting on read). Not started. Note: Model Atlas has **no Apicurio backend anymore** (its
   README is outdated), so the content-addressed snapshot store and `FingerprintService` must be
   built as a Model Atlas extension (remaining backends there: file + Lucene).
6. **Manifests**; fault policies `RESYNC` + `SKIP_AND_MARK` only.
7. **One** transport binding: CloudEvents over MQTT *or* RabbitMQ — not both.
8. **Metadata projections** (index holder, derived versions).

Explicitly out of v1 (reserved in the models, documented, not built): `ELEMENT_WISE` arrays,
selective mid-history undo, `BUFFER_AND_WAIT`/`QUARANTINE` fault policies, continuous aggregates,
the EMF-Compare→ChangeSet offline converter, the privacy advisor, a second transport binding.

Also still open from the Mongo work-package list (`docs/discussion-mongo-persistence.md` part 3):
id-only lazy projection as an option, PostgreSQL/FerretDB evaluation.

## 5. Build & test

```bash
./gradlew build                    # everything except @Tag("perf")
./gradlew :MODULE_NAME:test        # single module
./gradlew perfTest                 # @Tag("perf") only, ignoreFailures=true
./gradlew codeCoverageReport       # JaCoCo XML + HTML
```

* OSGi integration tests run from `org.eclipse.fennec.persistence.test/test.bndrun`;
  JaCoCo exec lands in `generated/tmp/testOSGi/generated/jacoco.exec`.
* Test reports are written to `<module>/generated/test-reports/`, **not** to `build/test-results`.
* **Mongo tests start a container via the docker CLI, with a podman fallback**
  (`MongoContainerSupport`, TCK `MongoTestSupport`). Override the CLI with
  `-Dmongo.container.cli`, or point at an existing server with `-Dmongo.uri` / `MONGO_URI`.
  Without a container they **skip**; CI on ubuntu runners does run them for real.
* Bnd libraries come from the Data In Motion Nexus and Sonatype snapshots (`cnf/build.bnd`,
  `cnf/central.mvn`); the `fennecCodec` library supplies the emf.codec + metadata bundles.

## 6. Working conventions (please keep)

House rules established over the previous sessions — not derivable from the repo alone.

* **Logging = `java.util.logging` (JUL)** only. No SLF4J, no OSGi LogService.
  Since #19: *diagnostics are the contract, logging is derived* — log only at boundaries where
  diagnostics would otherwise be lost (legacy APIs, deploy path); result APIs never log.
* **Always use Java imports, never fully-qualified class names** in code bodies.
* **Every fix ships with test coverage**, and the coverage is verified critically — no "looks fine".
  A full build incl. OSGi ITs must be green before anything counts as done.
* **Commits only on explicit instruction**, with `Signed-off-by: Mark Hoffmann`. **Never push.**
* **`src-gen*` is generated** — never hand-edit. For `.ecore`/`.genmodel` code generation, ask Mark
  to run the generator (faster than scripting it).
* **Answer questions first, wait for the decision** — don't jump into edits when a question was asked.
* **Non-OSGi test migration:** only move a test out of OSGi if OSGi isn't the subject of the test,
  and never bypass DDL generation to make something pass.
* **CycloneDX / Gradle-style dependency tooling does not apply here** — dependencies live in bnd
  repositories, not in Gradle configurations. Use Eclipse Dash (§4.2).
* **CI lesson:** the license-header gate runs *before* the Gradle job, so a header violation makes
  the build silently never run. Check the CI run after every push.
* **bnd gotchas:** new bundle imports must be added to the `test.bndrun` `-runbundles` **and** the
  tck/test `-testpath`, else `NoClassDefFoundError`. `resolve.test` writes only to
  `generated/test.bndrun` — mirror the resolved `-runbundles` into the checked-in file by hand.
  A `.gitkeep` in two source roots collides in bnd's `processResources` (use `src-gen/.gitignore`).
